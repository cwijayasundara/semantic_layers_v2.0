candidate_evidence computes several of the step 5 facts for the change URIs you name: the dependency path from the alerting application down to each change's application with the state of every call on it, the minutes from the change to the onset and to the alert, the telemetry already present below it before it landed (split by whether an earlier change explains it), the other changes on its application, and the engine's chain through it. It examines only the changes you name, and it draws no conclusion. Name your candidates in batches of up to eight. Read every fact for every candidate, and weigh them yourself in step 6.
